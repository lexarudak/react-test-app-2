# React code reuse patterns (custom hooks, HOC, render props)

## Базовые принципы

- **Компоненты** - для инкапсуляции UI
- **Хуки** - для инкапсуляции логики

Компоненты хорошо бы делить на умные и тупые. Тупой компонент не хранит логики кроме обслуживающей самого себя. Ну типа кнопка просто принимает текст и хендлеры снаружи. Это повышает ее переиспользуемость. Далее проект можно организовывать по FSD или чему-то похожему. 

## Паттерны переиспользования

### Custom hooks
Кастомные хуки нужны для того чтобы переиспользовать логику в разных местах. А также чтобы скрыть детали реализации усложняющие прочтение компонента. Например всю логику логирования я выношу в кастомный хук. Он не переиспользуется нигде, но мне просто не нужны детали логирования в компоненте. Мне просто нужно забирать из хука функции-хендлеры для логирования.
### HOC (Higher-Order Components)
ХОК - это компонент высшего порядка. Он принимает в себя другой компонент и возвращает его модифицированную версию. Например может принять лист айтемов и вернуть его мемоизированный вариант. Ну или например это может быть компонент который хендлит загрузку и ошибку. И если их нет - показывает чайлда. А если есть - спиннер или баннер с ошибкой.

### Render props
Рендер пропс - это паттерн, в котором компонент принимает айтемы и функцию, с помощью которой будет их рендерить. Надо это в случаях когда мы хотим принимать решения о рендере айтема исходя из информации, доступной в родителе. Это своего рода форматтер.

```ts
<ul>
  {items.map((itemProps, index) => (
    <li key={itemProps.id}>
      {formatter(SmartPanelMetadataItem, itemProps)}
      {index < items.length - 1 && separator}
    </li>
  ))}
</ul>
```

### Children as function
Когда компонент чайлдом принимает функцию, из которой можно достать интересные аргументы. Например во всяких либах типа формика можно чайлдом передать функцию. И из аргумента достать объект с хендлерами. То же самое касается если твой родительский компонент имеет контекст. Можно доставать его хендлеры.

### Compound Components pattern
```ts
// Компоненты работают вместе через контекст
<SmartPanel>
  <SmartPanel.Title {...smartPanelTitle} />
  <SmartPanel.Description {...smartPanelDescription} />
  <SmartPanel.Metadata {...smartPanelMetadata} />
</SmartPanel>
```

### Provider pattern
Компонент-обертка который предоставляет данные/логику через context всем детям.

## Сравнение паттернов - когда что использовать

- **Custom hooks** - современный стандарт для логики
- **HOC** - legacy, но иногда нужен для библиотек. Ну или как в моем примере
- **Render props** - когда нужна гибкость рендеринга. Опять же как в моем примере
- **Children as function** - упрощенная версия render props
- **Compound components** - для сложных UI компонентов

## Best practices

Короче чем проще тем лучше. И не создавайте ссылки хуками. Возвращайте из хуков функции для их создания. Чтоб можно было в мапе юзать и вызывать кондишенали.
