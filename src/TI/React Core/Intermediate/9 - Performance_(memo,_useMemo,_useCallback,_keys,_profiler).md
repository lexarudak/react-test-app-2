# Performance (memo, useMemo, useCallback, keys, profiler)

Так, начнем с того, что React сам по себе уже достаточно оптимизирован. Работа через Fiber минимизирует обращения к DOM. Инструменты типа батчинга и eager обновления стейта тоже оптимизируют выполнение кода. Теперь уберем за скобки оптимизацию общую для любого кода, раз мы говорим про React. Например, про пагинацию и бесконечный скроллинг. И в итоге что мы понимаем под оптимизацией.

## Базовые принципы оптимизации

Обычно под оптимизацией в React понимают сокращение количества ререндеров компонентов. Ререндер не означает перерисовку интерфейса - это просто выполнение тела функции компонента. Обычно достаточно базовых принципов построения приложения для хорошей оптимизации:

- держать стейт как можно ниже, чтобы не провоцировать ререндер ненужных компонентов
- пробрасывать компоненты чилдренами. Если ты рендеришь компонент внутри другого компонента, не передавая в него пропсы из этого компонента-обертки, то надо его пробросить как children. Тогда ререндер обертки не спровоцирует ререндер чайлда
- следить за зависимостями в useEffect
- использовать точечные селекторы из стейт-менеджеров, чтобы реагировать только на изменения нужных полей в стейте. создавать их через createSelector чтобы мемоизировать
- выносить все что можно из компонента: создание функций, объектов и так далее
- использовать постоянные неизменяемые ключи в списках для рендера. можно и индексы если порядок и кол-во айтемов не меняется. если меняется - ключи должны быть посоянными и уникальными. так реак поймет что айтем с 1 места перехал на второе и отрендерить только айтем в начале и не будет перерендеривать весь список. ну и ререндер всего списка сбрасывает состояния ввода юзера например

## Дополнительные инструменты оптимизации

Если этого не достаточно, то следует прибегать к дополнительным инструментам:

**memo** - это функция высшего порядка, которая принимает 2 аргумента: компонент и функцию сравнения. Если второй аргумент не передавать, то компонент просто мемоизируется. Это значит что ререндер родителя не будет провоцировать его ререндер - только изменение пропсов будет.

Второй аргумент - функция, которая принимает 2 аргумента (старые и новые пропсы) и возвращает `true`, если пропсы равны (НЕ ререндерить), или `false`, если разные (ререндерить). Позволяет сравнить их кастомно. (А в новом React вообще можно использовать React Compiler, который по умолчанию все компоненты оборачивает в memo)

**useMemo** - хук, который мемоизирует результат выполнения функции. Принимает функцию и массив зависимостей. Нужен при сложных вычислениях в этой функции и для сохранения ссылочной целостности объектов/массивов

**useCallback** - мемоизирует создание функции. Принимает функцию и массив зависимостей.

**React.lazy + Suspense** - ленивая подгрузка части кода. например если код используется редко или не сразу после загрузки страницы. его можно подгружать по требовнияю (по клику на кнопку например). Это уменьшит размер бандла и ускорит отрисовку страницы. пу сути это Code splitting. часть кода выделяется в отдельный чанк и запрашивается отдельно, с того же сервака на котором деплой лежит

А **profiler** - просто тулза, позволяющая следить за временем рендера компонента и их количеством.

## Антипаттерны (важно!)
Когда memo/useMemo/useCallback **вредят**:
- Простые вычисления (сравнение дороже самих вычислений)  
- Примитивные пропсы в memo
- useMemo с пустыми зависимостями

*Дополнительные техники:*
Virtualization для огромных списков (react-window)
Debouncing/throttling для частых обновлений (поиск, скролл)

Code splitting на уровне роутов
// Каждая страница - отдельный chunk
const HomePage = lazy(() => import('./HomePage'))
const AboutPage = lazy(() => import('./AboutPage'))
const ContactPage = lazy(() => import('./ContactPage'))

<Suspense fallback={<div>Loading...</div>}>
  <Routes>
    <Route path="/" element={<HomePage />} />
    <Route path="/about" element={<AboutPage />} />
    <Route path="/contact" element={<ContactPage />} />
  </Routes>
</Suspense>

// Результат: 
// main.js (500KB) - только роутер + общий код
// home-page.js (800KB) - загружается при переходе на "/"
// about-page.js (600KB) - загружается при переходе на "/about"
// contact-page.js (300KB) - загружается при переходе на "/contact"
