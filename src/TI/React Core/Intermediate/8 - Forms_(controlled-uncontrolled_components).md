# Forms (Controlled / Uncontrolled Components)

Часто в React для обработки форм используют дополнительные библиотеки.  
Самые популярные: **React Hook Form** и **Formik**, а для валидации — **Yup**, **Zod** и другие.

---

## Formik
- Работает через **React Context**.
- Основан на **контролируемых компонентах**.
- Доступ к вложенным полям реализован через собственные утилиты `getIn` / `setIn` (по логике lodash `get`).
  
```tsx
<Formik initialValues={...} onSubmit={...}>
  <Form>
    <Field name="username" />
    <Field name="password" />
  </Form>
</Formik>
```

---

## React Hook Form
- Основан на **неконтролируемых элементах**.
- Не ререндерит все поля и форму при вводе символа.
- **Валидация на лету** происходит в обработчиках событий:
  - На `onChange` вызывается валидатор.
  - Если ошибка появляется — она сохраняется в state.
  - Если ошибка пропадает — удаляется из state.

---

## 1. Контролируемые компоненты (Controlled)
Компонент привязывается к state:
- В `value` передаётся значение из state.
- В `onChange` — setter для обновления значения.

Позволяет иметь доступ к данным **в любой момент времени** и гибко ими управлять:
- Пример: переводить ввод сразу в верхний регистр или запрещать определённые символы.

**Источник правды:** state React. Инпуты в DOM просто отображают значение, полученное через `value`.

**Пример оптимизации:**  
Если компонент содержит много полей, можно использовать `useReducer`.  
В больших формах — держать state каждого поля в отдельном компоненте, поднимая `value` вверх только при изменении **статуса** (валидация, submit).

**Юзаем, когда:**
- Нужно валидировать на лету.
- Нужно редактировать на лету.
- Один инпут зависит от другого.

---

## 2. Неконтролируемые компоненты (Uncontrolled)
Работаем через `ref`:
- Создаём реф с `useRef`.
- Передаём его в `ref` инпута.
- Читаем `ref.current.value` при нужном событии (submit, blur, onChange).

**Источник правды:** DOM (инпуты или тег формы).

**Начальное значение:** задаём через `defaultValue` / `defaultChecked`. При вводе данные меняются только в DOM — React читает их через `ref`.

Чтобы не вешать отдельный ref на каждый элемент, можно работать с формой целиком:

```tsx
export const FormApp = () => {
  const ref = useRef<HTMLFormElement>(null);

  const onSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    if (ref.current) {
      const formData = new FormData(ref.current);
      const username = formData.get('username');
      const password = formData.get('password');
      console.log('Form Data:', { username, password });
    }
  };

  return (
    <form ref={ref} onSubmit={onSubmit}>
      <input type="text" name="username" defaultValue="123" />
      <input type="password" name="password" defaultValue="password" />
      <button>Submit</button>
    </form>
  );
};
```

**Юзаем, когда:**
- Формы с большим количеством полей (важна оптимизация).
- Хотим валидировать только по submit.
- Не хотим усложнять код.

---

## 3. Смешанный подход
Можно комбинировать:
- Зависимые друг от друга поля сделать **управляемыми** для валидации.
- Остальные данные собирать по submit через `formRef.current.elements` или `FormData`.

---

## Производительность Controlled-компонентов
- При `setState` на каждый введённый символ компонент **ререндерится**.
- Советы по оптимизации:
  - Валидировать поле локально (внутри его собственного компонента).
  - Поднимать изменения в общий state формы **только при смене статуса** (ошибка ↔ не ошибка).
  - Это позволит избежать ререндера всей формы при каждом вводе символа.
